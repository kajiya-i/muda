# ADR-0005: 多通貨に対応した複式の台帳でお金の動きを記録する

## Status

Proposed

## Date

2026-10-02

## Context

ADR-0003 では、お金の動きを複式の台帳として記録し、1 つの取引の記録の合計を常に 0 とすることを決めた。その後、各国の家族が使うことと、1 つの家族の中で通貨を両替して外貨で支出することを要件に加えた（ADR-0004）。

ADR-0003 の要件 R1〜R7 に加えて、次の要件がある。

- R8: 家族はそれぞれの基準通貨で家計を管理できる。
- R9: 通貨の両替（例: 15,000 円を 100 ドルに両替する）と、両替した外貨での支出を記録できる。
- R10: 通貨ごとの残高（例: 家計に 40 ドル残っている）を正確に表示できる。

円とドルの金額は足し合わせられないため、ADR-0003 の「取引の記録の合計は常に 0」のままでは両替を記録できない。

実際の両替のレートは、両替所や銀行、カード会社ごとに手数料が上乗せされて異なる。市場の為替レートは、公開している機関自身が情報提供の目的に限るとしているものもある。

この ADR は ADR-0003 を置き換え、多通貨に対応した台帳の構造を決める。

## Options Considered

### Option 1: 記録のときに基準通貨に換算する

- 概要: 台帳は基準通貨だけで持ち、外貨の支出は記録のときに為替レートで基準通貨に換算して記録する。
- 利点: ADR-0003 の構造をそのまま使える。
- 欠点: 手元にある外貨の残高が分からない（R10）。記録に使う為替レートが必要になり、実際の両替のレートと異なる金額が台帳に入る。

### Option 2: 通貨ごとに独立した台帳を持つ

- 概要: 円の台帳とドルの台帳を別々に持つ。
- 利点: 各台帳は ADR-0003 の構造をそのまま使える。
- 欠点: 両替が 2 つの台帳にまたがり、1 つの取引として記録できない。片方の台帳だけに記録される誤りを防げない。

### Option 3: 1 つの台帳で勘定に通貨を持たせ、通貨ごとに合計を 0 にする

- 概要: 勘定に通貨を持たせ、取引の記録の合計を通貨ごとに 0 とする。両替は、両替の勘定を間に挟んで記録する。
- 利点: 両替を 1 つの取引として記録できる。通貨ごとの残高が正確に求まる（R10）。為替レートを使わずに、実際に動いた金額だけを記録できる。お金が消えたり増えたりしないことを、通貨ごとに構造的に保証できる。
- 欠点: 勘定の数が通貨の数だけ増える。両替の勘定という概念を理解する必要がある。

## Decision

Option 3 を採用し、多通貨に対応した複式の台帳でお金の動きを記録する。ADR-0003 の決定のうち、次の点は引き継ぐ。

- 会計の専門用語を使わず、符号付きの金額で表す。プラスはその勘定にお金が入ったこと、マイナスは出たことを表す。
- 取引は、それを生じさせた申請への参照を持つ。
- カテゴリは勘定にせず、支出の勘定への記録の属性として持つ。
- 残高は保存せず、記録から毎回導出する。
- 記録を変更・削除せず、打ち消しの取引を追加して訂正する。

### 勘定

勘定は次の 5 種類とし、それぞれ通貨を持つ。同じ種類の勘定でも、通貨が異なれば別の勘定とする。

| 勘定 | 意味 |
|---|---|
| 家計 | 家計にあるお金 |
| 未精算 | 家計がそのメンバーに返すべきお金。メンバーごとに持つ |
| 支出 | 使われたお金 |
| 拠出 | 家計の外から入ってきたお金 |
| 両替 | 両替で、ある通貨から別の通貨に移ったお金 |

### 取引の制約

1 つの取引に属する記録の金額の合計は、通貨ごとに 0 でなければならない。

### 仕訳

ADR-0003 の 4 種類のお金の動きは、同じ通貨の勘定の間で記録する。両替は次のように記録する。

| お金の動き | 記録 |
|---|---|
| 両替（円からドル） | 家計（円）−、両替（円）+、両替（ドル）−、家計（ドル）+ |

### 為替レート

為替レートは台帳に記録しない。両替は、実際に渡した金額と受け取った金額の組として記録する。概算の表示などに使う参考のレートは、台帳の外で扱う。

### 残高超過の判定

家計残高を超える支払いの判定（R3）は、通貨ごとに行う。

### 導入の順序

MVP では、家族の基準通貨だけで運用する。両替と外貨の家計は MVP の後に追加する。台帳の構造は最初から多通貨に対応させ、後から通貨を加えるときに既存の記録の移行が不要になるようにする。

### Tradeoffs

複数の通貨を正確に扱えることと、為替レートに依存せずに実際に動いた金額だけを記録できることを得る代わりに、勘定の数の増加と、両替の勘定という概念を学ぶコストを受け入れる。基準通貨での集計（例: ドルの支出が円でいくらだったか）は、この構造の上に後から追加する。

### Confidence

High

通貨ごとに記録の合計を一致させ、通貨の両替を専用の勘定で扱う方法は、多通貨を扱う台帳で確立した方式である。基準通貨での集計の方法は未決定だが、台帳の記録から導出できるため、この決定とは独立に後から決められる。

## Consequences

### Positive

- 両替を 1 つの取引として記録でき、片方の通貨だけが記録される誤りを防げる。
- 通貨ごとの残高が、勘定ごとの記録の合計で正確に求まる。
- 為替レートを取得できなくても、お金の記録は止まらない。
- 両替を MVP の後に追加するとき、既存の記録の移行が不要である。
- ADR-0003 の利点（お金の総量の構造的な保証、残高の導出、純粋な関数によるテスト）を引き継ぐ。

### Negative

- 勘定の数が、通貨の数に比例して増える。
- 両替の勘定の残高は、為替の差益・差損を表す複数の通貨の金額の組になり、その解釈が必要になる。
- 基準通貨での集計を行うには、両替時の実際のレートを記録から求める処理か、参考のレートを使う処理を別途作る必要がある。
- ADR-0003 と同様に、残高超過の判定には、データベースのトランザクションによる並行性の制御が必要になる。

## Compliance

- 取引を表すドメインの型は、コンストラクタで記録の合計が通貨ごとに 0 であることを検証し、そうでない取引を作れないようにする。
- 残高を求める処理は純粋な関数とし、勘定と通貨の組ごとに合計を求める。両替を含む取引について単体テストを書く。
- 台帳の記録に為替レートの列が追加されていないことを、コードレビューで確認する。
- ADR-0003 の Compliance の項目（記録を更新・削除しないこと、残高を保存しないこと）を引き継ぐ。
- MVP の後に両替を追加する際、残高を求める処理を変更せずに済んだかを記録し、この判断の妥当性を評価する。
