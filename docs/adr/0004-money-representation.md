# ADR-0004: 金額を最小単位の整数と通貨コードで表す

## Status

Accepted

## Date

2026-10-02

## Context

このサービスは、各国の家族が使うことを想定する。また、日本円を持つ家族がアメリカでドルに両替して買い物をするなど、1 つの家族の中で複数の通貨を扱う場面がある。

金額の表現には、次の要件がある。

- M1: 台帳の記録は符号付きの金額を持ち、取引の記録の合計がちょうど 0 になることを検証する（ADR-0003、ADR-0005）。
- M2: 申請額、購入額、入金額など、利用者が入力する金額は必ず正の値である。
- M3: 承認額と購入額、家計残高と支払額を比較できる。
- M4: 通貨によって小数点以下の桁数が異なる（日本円は 0 桁、米ドルは 2 桁など）。
- M5: Go のバックエンドと TypeScript のフロントエンドの間で、金額を正確に受け渡す。
- M6: 金額の計算が、ドメインのロジック以外で勝手に行われないようにする（`docs/rules/backend.md` §5、§7、`docs/rules/frontend.md` §10）。
- M7: 異なる通貨の金額を、誤って足したり比べたりしない。

この ADR では、金額を Go、TypeScript、API でどう表すかを決める。台帳の構造は ADR-0005 で、データベースの列の型は永続化の方式の ADR で決める。

## Options Considered

### Option 1: 浮動小数点数

- 概要: Go の `float64`、TypeScript の `number` で金額を持つ。
- 利点: 言語の標準の型をそのまま使える。
- 欠点: 小数を正確に表せず、セント単位の計算で誤差が出るため、取引の合計がちょうど 0 になることを検証できない（M1）。型としてはただの数値なので、金額以外の数値と取り違えるミスを防げない（M6）。

### Option 2: 10 進数のライブラリ

- 概要: `shopspring/decimal`（Go）、`decimal.js`（TypeScript）などで、小数を含む金額を正確に計算する。
- 利点: 小数を含む計算を正確に行える。
- 欠点: 利息の計算のような小数の演算は不要であり、Go と TypeScript の両方に依存ライブラリが増える。

### Option 3: 整数の円

- 概要: 金額を整数の円で持ち、通貨は持たない。
- 利点: 最も単純で、日本円だけを扱うなら要件を満たす。
- 欠点: 日本円以外の通貨を扱えない（M4、M7）。後から通貨を加えると、蓄積したすべての記録の移行が必要になる。

### Option 4: 最小単位の整数と通貨コード

- 概要: 金額を、その通貨の最小単位で数えた整数と、ISO 4217 の通貨コードの組で持つ（例: 19.99 米ドルは 1999 と USD）。
- 利点: 整数で正確に計算でき、合計がちょうど 0 になることを検証できる（M1）。どの国の通貨も扱える（M4）。通貨の異なる金額の演算を検出できる（M7）。依存ライブラリが不要である。
- 欠点: 通貨ごとの小数点以下の桁数を管理する必要がある。利用者が入力した小数の金額を、最小単位の整数に変換する処理が必要になる。

## Decision

Option 4 を採用し、金額を最小単位の整数と通貨コードの組で表す。

### 金額の型

- 金額は、最小単位で数えた 64 ビットの整数と、通貨コードの組とする。
- 扱える通貨は、通貨コードと小数点以下の桁数をコードで定義した一覧に限る。通貨を追加するのはアプリケーションの変更とする。
- 異なる通貨の金額同士の演算や比較はできない。演算しようとした場合はエラーとする。
- 台帳の記録に使う符号付きの金額と、利用者が入力する正の金額を、別の型にする。正の金額の型はコンストラクタで正であることを検証し、正の金額から符号付きの金額への変換だけを許す。

### 各層での表現

- Go: フィールドを公開しない構造体で包み、コンストラクタを通してしか値を作れないようにする。使える演算は、型に定義したメソッドだけにする。
- API: `{"amount": 1999, "currency": "USD"}` のように、最小単位の整数と通貨コードを受け渡す。
- TypeScript: `Schema` で、金額が整数であることと、通貨コードが扱える通貨の一覧に含まれることを検証してから、ブランド付きの型にデコードする。
- 画面での表示（`$19.99`、`¥3,480` など）は、表示の直前でだけ行い、計算は最後まで整数のまま扱う。

### 基準通貨

家族はそれぞれ基準通貨を持つ。基準通貨は、その家族の家計で主に使う通貨である。

### 為替レート

金額の型は為替レートを持たない。通貨の換算は表示の目的に限り、台帳の記録には使わない（ADR-0005）。

### Tradeoffs

複数の通貨を正確に扱えることと、後から通貨を加えるための移行が不要になることを得る代わりに、通貨ごとの小数点以下の桁数の管理と、入力された小数の金額を整数に変換する処理を受け入れる。

### Confidence

High

最小単位の整数と通貨コードの組は、複数の通貨を扱うシステムで広く使われている方式である。今回の要件では小数の演算が不要なため、10 進数のライブラリを使う利点がない。

## Consequences

### Positive

- 金額の計算に誤差が出ず、取引の合計がちょうど 0 になることを検証できる。
- 各国の家族が、それぞれの通貨で使える。
- 異なる通貨の金額を誤って計算する誤りを、型と演算のエラーで防げる。
- 依存ライブラリなしで実装できる。

### Negative

- 通貨ごとの小数点以下の桁数を、Go と TypeScript の両方で管理する必要がある。
- 利用者が入力した `19.99` のような値を、最小単位の整数 `1999` に変換する処理と、その検証が必要になる。
- 扱う通貨を増やすたびに、アプリケーションの変更が必要になる。

## Compliance

- 金額の計算に浮動小数点数を使っていないことを、コードレビューで確認する。
- 金額の型のコンストラクタと演算について、異なる通貨の演算がエラーになること、正の金額の型に 0 以下の値を渡せないことを単体テストで確認する。
- API で受け取った金額は、Go と TypeScript の両方で、扱える通貨と整数であることを検証してから使う。
