# 相談

用語は [ユビキタス言語](README.md#ユビキタス言語) に従う。

## 相談が持つもの

| 持つもの | 意味 |
|---|---|
| 相談した家族 | 相談を出した家族 |
| ほしいもの | 買いたいものの名前 |
| 相談した金額 | 買いたいものの金額。おうちのお金で、0 より大きい金額にする |
| つかいみち | お金を何に使うかの分類 |
| ひとこと | 家族に伝えたいこと。書かなくてもよい |

## 相談のようす

```text
したがき ──出す──▶ いいね待ち ──いいねがそろう──▶ いいね済み ──買ったよ報告──▶ 買ったよ ──おかえし──▶ おかえし済み
                      │                              │                          （たてかえのときだけ）
                      ├──見送る──▶ 見送り            ├──月の終わり──▶ 時間切れ
                      └──とりやめる──▶ とりやめ      └──とりやめる──▶ とりやめ
```

おさいふから払った買い物は「買ったよ」で終わり、たてかえで買った買い物は「おかえし済み」で終わる。

### したがき

- したがきは、相談した家族だけが見られる。
- したがきのあいだは、相談が持つものを自由に書き直せる。したがきを消すこともできる。
- したがきは家族に向けた事実ではないので、イベントとして記録しない。

### 出す

- したがきを出すと、いいね待ちになる。
- 出すときに、いいねする人と、相談した金額がどきどきラインを超えているかを決めて記録する（[いいね](like.md) を参照）。
- 出したあとは、相談が持つものを書き直せない。変えたいときは、とりやめて相談し直す。

### いいねと見送り

いいねと見送りのルールは [いいね](like.md) に従う。

- 必要ないいねがそろうと、いいね済みになる。そのときに、相談した金額が使う予定のお金として確保される（[今月のやりくり](budget.md) を参照）。
- 1 人でも見送ると、見送りになる。

### とりやめ

- 相談した家族は、いいね待ちかいいね済みの相談を、とりやめられる。
- 相談した家族がおうちから外れると、その家族のいいね待ちといいね済みの相談は、すべてとりやめになる（[おうちと家族](household.md) を参照）。

### 時間切れ

いいね済みの相談には、2 つの期限がある。

| 期限 | いつまで | 意味 |
|---|---|---|
| 買える期限 | いいねがそろった月の終わり | この期限までに買う |
| 報告の期限 | いいねがそろった月の翌月の 7 日の終わり | この期限までに買ったよ報告をする |

- 報告の期限を過ぎても買ったよ報告がなければ、時間切れになる。
- 2 つの期限は、おうちの時間で、いいねがそろったときに決めて記録する。あとからおうちの時間を変えても、すでに決まった期限は変わらない。
- 時間切れかどうかは、記録した報告の期限と今の時刻から判断する。
- 買える期限を過ぎたあとに買うことはできない。ただし、買ったかどうかは家族の自己申告による。

### 買ったよ報告

- 相談した家族は、いいね済みの相談について、買ったよ報告ができる。
- 買ったよ報告では、買った金額と払い方（おさいふから払う、たてかえ）を伝える。
- 買ったよ報告は、報告の期限まで、つまり月をまたいでもできる。買った日は伝えない。正直に報告する限り、買ったのは必ずいいねがそろった月のうちだからである。
- 買ったよ報告をすると、買ったよになり、買った金額は、報告した月ではなく、いいねがそろった月の使ったお金に加わる。

### おかえし

- たてかえで買った買い物は、おさいふ係がたてかえのおかえしをすると、おかえし済みになる。
- おかえしのルールは [おうちのおさいふ](wallet.md) に従う。

## イベント

相談のようすが変わった事実を、イベントとして記録する。イベントは過去に起きた事実であり、あとから変えない。

### すべてのイベントが持つもの

| 持つもの | 意味 |
|---|---|
| イベント ID | イベントを一意に表す ID。同じイベントを二重に扱わないために使う |
| 相談 ID | どの相談のイベントか |
| バージョン | その相談の何番目のイベントか。同じ相談の中で一意である |
| 種類 | イベントの種類 |
| 起きた日時 | イベントが起きた日時 |
| した家族 | 誰の操作で起きたか。時間の経過などで起きたときはシステム |
| 内容 | 種類ごとに異なる内容 |
| 内容の形のバージョン | 内容の形を将来変えたときに、古いイベントを読み分けるため |

### イベントの種類

| イベント | 起きるとき | 内容 |
|---|---|---|
| `ConsultationSubmitted` | 相談を出した | ほしいもの、相談した金額、つかいみち、ひとこと、いいねする人、どきどきラインを超えているか |
| `ConsultationLikeGiven` | おさいふ係がいいねした | いいねした家族。1 つ目のいいねでは、必要ないいねの数、いいねが 2 つ必要になった理由、そのときのやりくりの残り |
| `ConsultationLiked` | 必要ないいねがそろった | 買える期限、報告の期限 |
| `ConsultationSelfLiked` | 唯一のおさいふ係がじぶんでいいねした | 買える期限、報告の期限 |
| `ConsultationPassed` | おさいふ係が見送った | 見送った家族、見送りの理由、コメント |
| `ConsultationWithdrawn` | とりやめになった | とりやめになったわけ（相談した家族がとりやめた、相談した家族がおうちから外れた） |
| `PurchaseReported` | 買ったよ報告をした | 買った金額、払い方 |
| `AdvanceRepaid` | たてかえのおかえしが済んだ | おかえしの ID |

- 最後のいいねでは、`ConsultationLikeGiven` と `ConsultationLiked` の 2 つのイベントが同時に起きる。いいね済みになったことを、いいねの数から推し量るのではなく、事実として記録するためである。
- 時間切れは、時刻から判断できるので、いまはイベントとして記録しない。時間切れを家族に知らせる必要が出てきたときに、`ConsultationExpired` を加える。
